# IT技术栈知识库（RAG 检索增强生成问答系统）

> 技术栈解析 · 学习路线推荐 · 全干货问答
>
> 开发日期：2026-09-21

## 一、项目背景与开发原因

**开发原因**：

1. **IT 知识庞杂、入门门槛高**：前端、后端、数据库、运维、AI……技术栈数量庞大且更新极快，初学者面对海量资料无从下手，网上内容碎片化、废话多。
2. **学习路线不清晰**：想知道"如何学习前端/后端/AI"，往往只能搜到零散文章，缺少从底层到进阶的系统化、分阶段路线。
3. **大模型通用问答存在幻觉与时效问题**：直接问 ChatGPT/DeepSeek 这类通用模型，回答可能编造内容、没有出处、无法针对自有知识定制。

**解决方案**：本项目基于 **RAG（检索增强生成）** 技术打造一个 IT 领域专属知识库问答系统：

- 知识库内容为团队整理的技术栈解析（29 篇）与学习路线（10 篇），**全是干货、无废话**，内容参考菜鸟教程（runoob.com）及官方文档等权威资料；
- 提问「什么是Vue」→ 系统先从知识库**向量检索**出最相关内容，再交给本地大模型组织回答，**答案有来源可追溯、不编造**；
- 提问「如何学习前端」→ 检索命中学习路线文档，输出**从底层基础到进阶实战的分阶段路线**，逐技术栈解释；
- 知识库未命中的问题走**兜底模式**：调用本地大模型通用知识回答，但回答前有显著标注「⚠️ 以下回答来自本地模型通用知识，非知识库内容」，与有来源的知识库回答明确区分。

## 二、系统功能

| 角色 | 功能 | 说明 |
| --- | --- | --- |
| 普通用户 | 注册 / 登录 | 注册即用，密码 bcrypt 加密存储，JWT 令牌有效期 24 小时 |
| 普通用户 | 智能对话 | RAG 流式回答（逐字输出）；命中知识库时回答底部展示来源标签，未命中时自动切兜底模式并显著标注 |
| 普通用户 | 停止生成 | 回答过程中可随时中断，已生成内容保留、补「已停止生成」标记并落库 |
| 普通用户 | 会话管理 | 新建 / 切换 / 删除会话，首问前 20 字自动作为会话标题，多用户数据互相隔离 |
| 管理员 | 上述全部功能 | 管理员也可正常对话 |
| 管理员 | 知识库管理（专属模块） | 上传 / 编辑 / 删除知识文档，操作后即时生效（自动重新向量化） |

> **权限说明**：知识库管理是**专属于管理员账号的功能模块**——普通用户界面上完全不显示该入口（导航隐藏 + 路由守卫拦截），后端接口另有管理员校验兜底，越权直连返回 403。
>
> **固定管理员账号**：`admin / admin123`

| 层 | 技术 | 选型原因 |

| RAG 框架 | LangChain | 集成向量库/大模型的标准框架，检索链组件化 |
| 向量数据库 | ChromaDB | 轻量嵌入式向量库，本地持久化、无需 Docker，最适合本项目规模 |

| 关系数据库 | SQLite + SQLAlchemy | 用户/会话/消息/文档元数据存储，零配置开箱即用 |
| 认证 | JWT + bcrypt | 无状态令牌鉴权 + 密码安全哈希 |

### 3.3 RAG 检索增强生成流程

```
知识入库（管理员上传/种子脚本）：
  文档(md/txt/pdf) → 解析纯文本 → 中文友好分块(500字/重叠50)
  → BGE 向量化(512维,归一化) → 写入 ChromaDB（携带 doc_id/标题/分类 元数据）
  → 种子库实际入库：39 篇文档 / 163 个向量块

问答检索：
  用户提问 → 加BGE查询指令前缀 → 向量化 → Chroma 余弦相似度检索 top4
  → 相似度阈值过滤（<0.25 视为未命中）
  → 命中：组装带来源标题的上下文（不编号，避免模型复述编号）
    → Prompt（干货风、不编造）→ Ollama 流式生成
  → 未命中：兜底模式——改用本地模型通用知识回答，回答开头插入显著标注
    「⚠️ 知识库未收录此问题，以下回答来自本地模型通用知识，仅供参考」
  → SSE 事件流：token*（逐字输出）→ done（会话ID + 去重后的来源列表）
    来源在回答结束后随 done 事件统一下发，前端渲染为回答底部的来源标签
  → 回答结束后落库；用户中途点「停止生成」也保存已生成内容并补停止标记
```

## 五、环境准备（一次性）

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Python | 3.10+ | 后端运行环境 |
| Node.js | 18+ | 前端构建环境 |
| Ollama | 最新版 | 本地大模型服务（官网 ollama.com 下载安装） |

**1. 启动 Ollama 并拉取模型**（打开 Ollama 桌面应用后执行）：

```bash
ollama pull qwen2.5:3b
```

> 机器配置较低可改拉更小模型：`ollama pull qwen2.5:1.5b`，并在 `backend/.env` 中把 `OLLAMA_MODEL` 改为对应名称。

**2. 后端依赖安装**（国内建议清华镜像，torch 约 2GB 请耐心等待）：

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows；Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
copy .env.example .env          # 首次需要（Windows；Linux/Mac 用 cp）；默认配置开箱即用
```

> `.env` 已被 `.gitignore` 排除，克隆仓库后需自行创建（一键启动脚本会自动复制）；代码内置同名默认值，即使缺失也能启动。

> BGE 向量模型首次使用会自动下载（约 100MB，已配置国内镜像 hf-mirror 加速）；下载后自动切换为**离线加载**，之后启动不再访问网络。

**3. 前端依赖安装**：

```bash
cd frontend
npm install
```

## 九、常见问题

| 问题 | 解决方案 |
| --- | --- |
| 对话报错连接失败 | 确认 Ollama 桌面应用已打开且模型已拉取（`ollama list` 检查） |
| 回答速度慢 | 属本地 CPU 推理正常现象（流式输出已缓解等待感）；换 `qwen2.5:1.5b` 提速 |

| 修改文档后提问没变化 | 编辑保存时已自动重新向量化；确认提问命中的是该文档（回答底部有来源标签） |
| 推送 GitHub 失败 / 仓库过大 | 根目录 `.gitignore` 已排除 `.venv`、`node_modules`、`data/`、`.env`、日志；若历史提交里已含这些文件，需清理 Git 索引后重新提交（见第十节） |

## 十、版本管理（.gitignore）

项目根目录 `.gitignore` 的作用是**把可重新生成的依赖、运行时数据和密钥挡在仓库之外**，保证克隆后仓库只有源码与知识文档。

### 10.1 忽略清单

| 忽略路径 | 体积 | 不提交的原因 |
| --- | --- | --- |
| `backend/.venv/` | 约 1.3 GB | Python 虚拟环境，含 torch，`pip install -r requirements.txt` 可重建 |
| `frontend/node_modules/` | 约 142 MB | npm 依赖，`npm install` 可重建 |
| `backend/data/` | 约 1.8 MB | SQLite 数据库 + Chroma 向量库 + 上传留档，`python -m app.seed_kb` 可重建 |
| `.env` / `.env.*` | 极小 | 含管理员密码与 JWT 密钥，只提交 `.env.example` |
| `__pycache__/`、`*.pyc` | — | Python 字节码缓存 |
| `*.log` | — | 运行日志（`start_backend.log` 等） |
| `.vscode/`、`.idea/`、`Thumbs.db`、`.DS_Store` | — | 个人 IDE 与系统文件 |
| `.workbuddy-ai/` | — | AI 工具的项目缓存，非交付内容 |

> 保留提交的内容：源码（`backend/app/`）、知识文档（`backend/docs/kb_seed/`）、依赖清单（`requirements.txt`、`package.json`、`package-lock.json`）、配置模板（`.env.example`）、启动脚本与文档。

### 10.2 已被跟踪的文件如何移除

`.gitignore` 只对**未跟踪**的文件生效。若大文件此前已被提交，需先从索引移除（本地文件保留）：

```bash
# 1) 清理 Git 索引（不删本地文件）
git rm -r --cached .
# 2) 按新的 .gitignore 重新加入
git add .
# 3) 提交
git commit -m "chore: 添加 .gitignore，移除依赖与运行时数据"
```

> 若历史提交中已存在大文件，`git commit` 后仓库历史体积仍然很大。此时需要重写历史（本项目仅 1 次提交，可直接用 `git commit --amend` 合并，再执行 `git gc --prune=now --aggressive` 回收空间），否则推送仍会因超限失败。
