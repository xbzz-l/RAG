# Kafka

## 一、是什么
Kafka 是 **LinkedIn 开源、Apache 顶级项目的分布式消息队列/事件流平台**。定位：高吞吐、持久化、可水平扩展的消息中间件，大数据与微服务解耦的核心组件。

## 二、核心知识
- **基础概念**：Producer（生产者）→ Broker（服务节点）→ Consumer（消费者）；Topic（主题，消息分类）；Partition（分区，Topic 水平拆分，并行与扩展基础）；Consumer Group（消费组，组内分区互斥消费）
- **消息模型**：发布-订阅；同一消费组内一条消息只被一个消费者消费（负载均衡），不同组各自全量消费（广播）
- **分区与顺序**：分区内消息严格有序，跨分区无序；partition = hash(key) % 分区数
- **持久化与高性能**：消息顺序追加写磁盘日志（Segment 分段）；顺序 IO + 零拷贝（sendfile）+ 页缓存；消息默认保留 7 天可重复消费
- **副本机制**：Replica 副本、Leader 负责读写、Follower 同步；ISR（In-Sync Replicas）保证高可用；acks 参数权衡可靠性与性能
- **偏移量 Offset**：消费者提交消费位置；重置策略（自动提交/手动提交）
- **常见问题**：消息重复（幂等消费）、消息丢失（acks=all + 手动提交）、消息积压（扩容分区与消费者）

## 三、作用与常用场景
- 异步解耦：下单/支付/物流等系统间异步联动
- 削峰填谷：秒杀/大促流量缓冲
- 日志收集与实时计算（大数据管道）
- 事件溯源与数据同步（Canal 同步 MySQL binlog 到 Kafka）

## 四、基于什么语言/底层原理
- **开发语言**：Scala 与 Java 编写；依赖 ZooKeeper/KRaft 管理元数据
- **高性能原理**：顺序磁盘 IO（比随机内存访问还快）、零拷贝、批量发送与压缩、分区并行

## 五、优缺点
| 优点 | 缺点 |
| --- | --- |
| 吞吐极高（百万级消息/秒） | 运维复杂（依赖 ZooKeeper/多组件） |
| 消息持久化，可重复消费 | 消息延迟高于 RabbitMQ（批量设计） |
| 水平扩展能力强 | 功能简单（无复杂路由，需自管理） |
| 生态庞大（大数据标准组件） | 中小项目属于过度设计 |

## 六、学习建议
先理解发布订阅模型与分区概念（对比 RabbitMQ 学习更高效）→ 搭建单机 Kafka 实操收发 → 副本与 ISR、acks 可靠性 → 消费组与偏移量 → 结合真实业务练手（如订单异步通知）。
