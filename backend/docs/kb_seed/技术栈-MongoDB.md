# MongoDB

## 一、是什么
MongoDB 是 **开源文档型（NoSQL）数据库**，以类 JSON 的 BSON 文档存储数据。定位：灵活 schema、水平扩展，适合非结构化/快速迭代的数据场景。

## 二、核心知识
- **文档与集合**：数据库 → 集合（Collection，类比表）→ 文档（Document，类比行）；文档字段可各不相同
- **CRUD**：insertOne/find/updateOne/deleteMany；查询操作符（$gt/$in/$regex）、更新操作符（$set/$inc/$push）
- **索引**：单字段/复合/多键（数组字段）/文本索引；与 MySQL 类似的索引优化思想
- **聚合管道 Aggregation**：$match/$group/$sort/$lookup（联表）/ $project 管道式数据处理
- **复制集 Replica Set**：主从复制 + 自动选举，保证高可用
- **分片 Sharding**：按片键水平拆分到多个分片，支撑海量数据
- **存储引擎**：WiredTiger（默认，文档级并发、压缩）
- **嵌入与引用**：一对多优先内嵌文档，多对多使用引用（权衡读写模式）

## 三、作用与常用场景
- 内容管理、日志存储、物联网时序数据
- 字段频繁变动的业务（灵活 schema）
- 地理空间查询（GeoJSON）
- 快速原型开发（无需预先建表）

## 四、基于什么语言/底层原理
- **开发语言**：C++ 编写；BSON（二进制 JSON）存储；查询经 JSON 语法解析执行
- **与 MySQL 对比**：无固定表结构、无跨文档事务（4.0+ 支持多文档事务但性能不如关系库）、不支持 JOIN（$lookup 性能受限）

## 五、优缺点
| 优点 | 缺点 |
| --- | --- |
| 文档模型灵活，字段随意增删 | 事务能力弱于关系型数据库 |
| 水平扩展（分片）天然友好 | 内存占用大（WiredTiger 缓存） |
| 聚合管道功能强大 | 复杂多表关联查询性能差 |
| 适合海量写入与快速迭代 | 数据一致性依赖复制集配置 |

## 六、学习建议
在掌握 MySQL 的基础上对比学习：理解文档模型与关系模型差异 → CRUD 与查询操作符 → 聚合管道 → 索引与复制集概念 → 用 Node/Spring Boot 项目实际集成一次。
