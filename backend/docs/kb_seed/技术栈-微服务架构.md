# 微服务架构

## 一、是什么
微服务（Microservices）是 **将单体应用拆分为一组独立小服务的软件架构风格**。每个服务围绕单一业务能力构建，独立开发、部署、扩展，服务间通过轻量协议（HTTP/RPC）通信。

## 二、核心知识
- **拆分原则**：单一职责、按业务域（DDD 领域驱动设计）、高内聚低耦合；拆得越小维护成本越高，需权衡
- **服务通信**：同步 RPC（Dubbo/gRPC）、同步 REST（HTTP+JSON）、异步消息（Kafka/RabbitMQ 解耦与削峰）
- **服务发现与注册**：注册中心（Nacos/Consul/Eureka）维护服务实例清单，调用方动态获取
- **API 网关**：统一入口（鉴权/限流/路由/聚合），如 Spring Cloud Gateway/Kong
- **配置中心**：集中管理多服务配置（Nacos/Apollo），支持动态刷新
- **负载均衡**：客户端负载均衡（Ribbon/Spring Cloud LoadBalancer）
- **容错与熔断**：熔断器（Sentinel/Hystrix）防止级联故障；超时/重试/降级/限流兜底策略
- **分布式事务**：CAP 理论权衡；方案：Seata（AT/TCC）、本地消息表、最终一致性（放弃强一致）
- **链路追踪**：分布式调用链监控（SkyWalking/Zipkin）
- **部署**：Docker 容器化 + Kubernetes 编排 + CI/CD 流水线

## 三、作用与常用场景
- 大型复杂业务系统（电商、金融、社交）
- 团队规模大、需要独立迭代的场景
- 弹性伸缩需求（热点服务独立扩容）
- 技术异构需求（不同服务不同语言/存储）

## 四、基于什么语言/底层原理
- **本质**：分布式系统的工程化组织方式；核心问题是网络通信带来的不确定性（延迟、失败、一致性）
- **常见技术栈**：Java（Spring Cloud Alibaba/Dubbo）、Go（Kratos/go-micro）、Python（FastAPI+注册中心）

## 五、优缺点
| 优点 | 缺点 |
| --- | --- |
| 服务独立部署迭代，敏捷性强 | 分布式复杂度爆炸：网络故障/一致性/调试难 |
| 可独立扩展，资源利用率高 | 运维成本高（部署/监控/链路追踪） |
| 技术栈灵活，故障隔离 | 数据一致性挑战（分布式事务难） |
| 适合大团队并行开发 | 小项目/小团队是过度设计 |

## 六、学习建议
前提：扎实的单体开发能力（Spring Boot 等）+ 网络与 Linux 基础。路径：理解拆分思想 → 注册中心/网关/配置中心逐个实战 → 熔断限流 → 分布式事务与消息最终一致性 → K8s 部署。切记：**小项目不要上微服务**。
